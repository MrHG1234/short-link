# 抖音云壳页 · 私信外链放行实验

## 这个包要验证什么

2026-11-06 已确认：开放平台应用是**网站应用**，私信外链的白名单入口只对**移动应用**开放，
所以 `www.xlianai.com` 无论怎么改 URL、改内容、换子域，在安卓私信里都会被拦。

现在剩下的唯一变量是**域名本身**：借抖音云分配的公网域名
（`<xxx>.service.douyincloud.run`，字节自家域名）能不能在私信里打开。
竞品 `mcdzz7` 用的就是这条路，25 天未封。

**一次部署即可得出结论，不需要改任何现有线上服务。**

## 文件说明

| 文件 | 用途 |
|---|---|
| `server.js` | 零依赖 Node 服务：监听 8000、`/v1/ping` 健康检查、渲染页面、全量请求日志 |
| `run.sh` | 启动脚本，必须可执行（Dockerfile 里已 chmod） |
| `Dockerfile` | 基于抖音云官方 Node 18 镜像，**不引用 Docker Hub** |
| `index.html` | 业务页（线上 `/brand` 企业介绍页原样改造），**对照组 B** |
| `probe.html` | 零脚本零外部资源中性页，**对照组 A** |
| `c.json` / `q1.png` / `og-user.jpg` | 按钮二维码、分享封面（从 121.40.36.150 原样拉的） |

页面里的 `__BASE__` 由 `server.js` 在响应时替换成真实域名，
所以 `og:url` / `og:image` 永远是绝对地址且与访问域名一致（避开 11/04 那个「og:url 与域名不一致 → 卡片不出图」的坑）。

## 抖音云的硬性规范（已按此改造）

| 项 | 要求 | 本包处理 |
|---|---|---|
| 端口 | **只能是 8000** | `server.js` 监听 0.0.0.0:8000 |
| 健康检查 | 必须实现 `GET /v1/ping` 返回 200 | 已实现，返回 `pong` |
| 启动脚本 | 根目录 `run.sh`，需可执行权限 | 提供，Dockerfile 里 `sed` 去 CRLF + `chmod a+x` |
| 基础镜像 | 不能引 Docker Hub（国内不通） | `i.public-cn-beijing.cr.volces.com/public/node:18-alpine` |
| 状态 | 服务必须无状态 | 纯静态，无落盘 |
| 时区 | 默认 UTC | Dockerfile 里 `ENV TZ=Asia/Shanghai` |
| 服务名 | 小写字母/数字/中划线，字母开头，≤20 字符 | 建议 `xliankegu` |

## 部署步骤

### 1. 建服务

抖音云控制台 → 服务列表 → **新建服务** → 自定义新建 → 容器服务

- 服务名称：`xliankegu`
- 创建时会同时生成 dev / prod 两个环境；只发 dev 就够测试
- 弹窗里如果问「外网入流量」→ **打开**

### 2. 配部署方式（三选一）

| 方式 | 需要什么 | 适合 |
|---|---|---|
| **Git 部署（推荐）** | 一个 Gitee / GitHub 仓库 + 授权 | 不用装 Docker，最快 |
| 镜像部署 | 本地 Docker + `dycloud` CLI | 本机有 Docker |
| 模板部署 | 仍需 Git 仓库，只是免写 Dockerfile | 本包已自带 Dockerfile，用不上 |

**Git 部署操作**：部署发布 → 服务设置 → 部署方式 → Git 部署 →
代码源选 Gitee → 授权 → 选仓库和分支 → Dockerfile 路径填 `Dockerfile` → 保存

### 3. 发布到 dev

部署发布 → 发布 → 部署方式 Git → 容器规格 1c1g 足够 → 发布，等流水线走完

### 4. 打开外网访问，拿默认域名

**这一步漏了会 100% 打不开。**

服务 → **访问控制** → 外网流量：

1. 打开「**外网入流量**」开关
2. 添加「**授权访问路径**」→ 填 `/`（或 `/*`，支持结尾通配符）
3. 打开「**域名访问**」开关 → 页面会显示**默认公网域名**

默认域名形如 `1mhw98cdgh0cq-env-ywmjc1zrbo.service.douyincloud.run`。

> 官方限制：**默认域名仅支持测试使用，限频 10 QPS；线上访问要求绑定自定义域名。**
> 但绑了自定义域名就变成自有域名，又回到抖音不认的老问题 ——
> 所以这条路只有「默认域名」有意义，量做大了一定会撞到这面墙。

## 测试矩阵（用小号测，一次做完）

拿到域名后（下称 `D`）：

| # | 发什么 | 场景 | 看什么 |
|---|---|---|---|
| 0 | `https://D/v1/ping` | 浏览器 | 返回 `pong`，证明服务活着 |
| 1 | `https://D/probe` | 私信粘贴文本 | **安卓**是否弹「第三方网页」 |
| 2 | `https://D/` | 私信粘贴文本 | 同上，业务页 |
| 3 | `https://D/probe` | 分享面板 → 分享给好友 → 卡片 | 卡片点开是否被拦 |
| 4 | `https://www.xlianai.com/brand` | 私信 | 基线对照，应该仍然被拦 |

## 判读

| 结果 | 结论 | 下一步 |
|---|---|---|
| 1 放行 | 字节域名对私信也放行 | **路成立**，把按钮接回现有后端，正式用 |
| 1 拦、3 放行 | 只认卡片形态 | 能用，但必须走分享面板生成卡片 |
| 1、3 都拦 | 私信只认「分享链接管理」报备，不认域名 | **路死**，转抖音小程序 |
| 4 不拦了 | 环境变了 | 别下结论，先重测基线 |

## 诊断辅助

`server.js` 把每次请求都打到 stdout（时间 / 路径 / 状态 / 大小 / Host / Referer / **完整 UA**）。
发布后在「部署运行 → 日志」里能直接看到安卓真机的 UA 和 Referer，
能区分「私信进入」和「分享卡片进入」，也能看到是否拿到 200 后仍被客户端拦截。

## 风险，先说清楚

1. **本质是在平台自己家里做平台收紧的事。** 抖音云和你的开放平台账号同一套体系，
   被判导流会**连带账号和挂在上面的资质**，比封一个自有域名贵得多。
2. 服务可被平台直接下线，容器与数据都在它上面，没有申诉渠道。
3. 域名不属于你，随时可能变。
4. **默认域名限频 10 QPS、官方写明仅供测试**，不是生产通道。

**结论：值得测（成本一次部署，能一次定性），但不适合当长期主力。**
长期唯一稳的形态是抖音小程序 —— 站内内容，这道风控墙根本不存在。
